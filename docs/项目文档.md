# 复利（CIM）项目文档

> 本文件反映**当前代码实际状态**，作为开发者上手与维护的权威参考。
> 产品层面的方案与路线图见同目录 [`产品与技术方案.md`](产品与技术方案.md)；本项目给 AI 协同的精简指引见仓库根目录 `AGENTS.md`。
>
> **命名说明**：包名 `com.wsy.ci` 中的 `CI` 即 **Compound Interest（复利）**。奖励点在本代码库最终命名为 **「CI 币」**（见 `ledger` 表与 `Economy.CI_PER_YUAN`），与产品方案草案中的「星尘」是同一概念的不同叫法。下文统称 **CI 币**。

## 一、项目概述

「复利」是一款**游戏化 AI 学习日程** Android 应用，单人自用，目标设备是三星 Galaxy Tab S11 Ultra 平板（横屏、左侧导航栏布局）。它把三件事合一：

1. **AI 自动排程**——用确定性算法把任务铺进日历，LLM 只负责自然语言解析与建议解释；
2. **游戏化经济**——专注时间产出 CI 币与经验，养成主线/支线、连击、头衔、商城；
3. **数据复盘**——纯本地计算的时间账本、计划 vs 实际、专注热力图、经济面板，可选 LLM 洞察。

定位：学习操作系统（Learning OS），全部数据本地存储，可导出备份。

## 三、技术栈

| 维度 | 选型 | 备注 |
|------|------|------|
| 语言 / UI | Kotlin + Jetpack Compose（`compose = true`）+ Glance（小组件） | Compose BOM 平台化引入 |
| 架构 | MVVM + Repository，单模块 `:app`，按 `core/`（可复用）与 `feature/`（按屏幕分包）分层 | 无 Hilt，手工 DI |
| 数据库 | Room（`version = 5`，`exportSchema = false`）+ SQLite | 全部本地，已有 v1→v5 migration，支持 JSON 导入 / CSV 导出 |
| 后台 | 前台服务（专注计时，`specialUse`）+ WorkManager（每日刷新） | `DailyRefreshWorker` |
| 排程引擎 | 纯 Kotlin 确定性算法（贪心 + 优先级），独立模块可单测 | 不依赖 LLM、不碰 db |
| LLM 接入 | OkHttp（OpenAI 兼容 `/chat/completions` 同步请求）+ 统一 `LlmGateway` 抽象 | 仅 API 端点（DeepSeek Pro/Flash、MiMo），无本地推理 |
| 配置存储 | DataStore + `androidx.security.crypto`（EncryptedSharedPreferences，Keystore 加密） | API Key 加密；路由表普通存储 |
| 序列化 | `kotlinx.serialization.json` | 导入导出、Entity 内 JSON 字段 |
| 测试 | JUnit4（`src/test`，JVM 单元测试） | 无 instrumented 测试 |

**构建参数**：`compileSdk = 35`，`minSdk = 31`，`targetSdk = 35`，`versionName = "0.1.0"`。

**注意**：依赖清单中**没有** Vico 图表库，也没有任何本地 LLM 推理库。若要做复盘图表或本地模型，需先补依赖。

### 4.2 依赖注入

没有 Hilt。`CiApp.container`（`AppContainer`）是手工 DI 容器，持有 `db`、`timerRepository`、`shopRepository`、`scheduleRepository`、`appSettings`、`llmSettings`、`llmService`。ViewModel 一律继承 `AndroidViewModel`，用 `(app as CiApp).container` 取依赖。新增 Repository 时往 `AppContainer` 加一行即可。

### 4.3 数据流

```
Room DAO 暴露 Flow
   → ViewModel 用 stateIn(viewModelScope, SharingStarted.WhileSubscribed(5000), 默认值) 转 StateFlow
   → Compose 收集
```

UI 不直接碰 DAO 以外的持久化。所有写库都经 Repository。

## 五、数据模型

Room `version = 5` 且 `exportSchema = false`，已有 `MIGRATION_1_2` 至 `MIGRATION_4_5`。以后改 Entity 必须提升版本并补 migration。共 9 张表：

| 表 | 实体 | 关键字段 / 关系 |
|----|------|----------------|
| `domains` | `DomainEntity` | 学习领域，承载头衔成长线（6 级 `titlesJson`）+ 累计 `totalExp` |
| `quests` | `QuestEntity` | 主线/支线定义，`type ∈ {MAIN, SIDE}`，`status ∈ {ACTIVE, DONE, ARCHIVED}`；主线含 `chaptersJson` 与 `deadlineEpochDay`，支线含 `streakDays` / `bestStreak` / `lastDoneEpochDay`；`parentQuestId` 让支线归属主线 |
| `tasks` | `TaskEntity` | 排程出的时间块实例；`status ∈ {PLANNED, RUNNING, DONE, SKIPPED}`，`locked` 标记锁定块；关联 `domainId` / `questId` |
| `sessions` | `SessionEntity` | 实际计时记录；`focus ∈ {COMPLETED, ABANDONED, OVERTIME}`；冗余存 `rewardCi` / `expGained` 便于复盘 |
| `ledger` | `LedgerEntity` | CI 币流水，`amount` 正为入账负为支出，`type ∈ {EARN_TASK, EARN_STREAK, EARN_LEVELUP, SPEND_SHOP, ADJUST}` |
| `shop_items` | `ShopItemEntity` | 货架常驻商品，`rarity ∈ {COMMON, RARE, EPIC, LEGENDARY}`，`savedCi` 储蓄进度 |
| `daily_picks` | `DailyPickEntity` | 每日 4 个折扣位（方案草案未列，已实际新增） |
| `purchases` | `PurchaseEntity` | 购买记录，`fulfilled` 标记是否真的兑现，冗余存 `rarity` |
| `blockers` | `BlockerEntity` | 占位事件（临时有事），重排引擎视为不可用时段 |

**表关系**：`domains` → `quests`（领域下承载主线/支线）→ `tasks`（排程实例）→ `sessions`（实际记录）→ `ledger`（CI 流水）。旁支：`shop_items` / `daily_picks` / `purchases` / `blockers`。

## 六、核心模块详解

### 6.1 排程引擎 `Scheduler`（纯 Kotlin，确定性，不依赖 LLM）

文件：`core/scheduler/Scheduler.kt`（无状态 `object`，不碰 db，可直接单测）。

- **固定不动**：`locked` 块、非 `PLANNED` 状态（已进行/完成/跳过）的任务。
- **不可用**：`blockers`（占位事件）与日窗口（默认 `07:00–23:00`）之外；`nowMinute` 之前的已过去时间也不可用。
- **可移动任务排序**：主线截止近者优先（`deadlineByQuestId`）→ 原起始时间 → id。
- **最小扰动**：原时间所在的空档还空着就不动，仅当原位置被挤占才找最早可用空档。
- **塞不下**：放进 `unplaced` 保留原时间并返回，交 UI 提示，**不静默丢弃**。
- 输出 `RescheduleResult`，含 `movedFrom()` 供 diff 预览。

### 6.2 经济系统 `Economy`（纯函数集合）

文件：`core/economy/Economy.kt`。**所有公式与阈值都在这里，不要把奖励计算散到 Repository 或 UI**。

- **CI 币** = `加权分钟 × 难度系数 × 专注系数 × (1 + 连击加成)`，向下取整。
  - 加权分钟（`weightedMinutes`）按单次专注时长分段累加：前 30 分钟 ×1、30–60 分钟 ×1.5、>60 分钟 ×2（例：40 分钟 = 45；90 分钟 = 135）。**只作用于 CI 币**，奖励坐得久。
  - 难度系数：轻松 0.8 / 一般 1.0 / 烧脑 1.3 / 攻坚 1.6。
  - 专注系数：按时完成 1.0 / 中途放弃 0.5 / 超时完成 0.9。
  - 连击加成：支线专属，7 天 +10%、30 天 +25%、100 天封顶 +50%。
- **经验** = `实际分钟 × 难度系数`（不吃时长阶梯，否则等级门槛失真）；与 CI 币**双轨，只增不减**。
- **锚定汇率**：`CI_PER_YUAN = 20`（1 元 ≈ 20 CI）。
- **头衔等级**：累计经验门槛 `600 / 2100 / 5400 / 12000 / 24000`，满级 6 级；升级一次性奖励 = 新等级 × 100 CI。
- **每日打卡**（`checkinReward` / `checkinStreak`）：当天首次专注发定额（1–2 天 20、3–6 天 40、7–13 天 80、14+ 天 150）；严格断签清零、不设补签。与支线 `streakBonus` 是两套独立机制。
- **结算落地**：`TimerRepository.stopSession` 一次调用里同时写 session、更新任务状态、记流水、结算领域经验与升级奖励、维护支线连击。

### 6.3 LLM 接入 `llm`

抽象见 `LlmGateway`（接口：`isAvailable` / `complete`）。调用方**不选模型**，而是声明 `LlmTaskType`：

| 任务类型 | tier | 默认端点 |
|---------|------|---------|
| `ROUTE_GEN` 学习路线生成 | HEAVY | DeepSeek V4 Pro |
| `REVIEW_ANALYSIS` 深度复盘 | HEAVY | DeepSeek V4 Pro |
| `NL_PARSE` 自然语言解析 | LIGHT | DeepSeek V4 Flash |
| `ITEM_PRICING` 商品估价 | LIGHT | DeepSeek V4 Flash |
| `TITLE_GEN` 头衔生成 | LIGHT | DeepSeek V4 Flash |
| `IMAGE_UNDERSTAND` 图片理解 | VISION | MiMo V2.5 |

- `LlmEndpoints` 预置 DeepSeek Pro/Flash 与 MiMo（视觉）三个端点；`resolveEndpoint`（在 `LlmSettings`）按 tier 路由到具体端点。
- **`resolveEndpoint` 返回 null 是正常路径**——表示用户关闭了该任务或没配 Key，调用方必须有离线兜底，不能报错。
- API Key 存 `EncryptedSharedPreferences`（Keystore 加密），路由表存普通 SharedPreferences，两者分开。
- 实现：`OpenAiCompatClient`（OkHttp，OpenAI 兼容）→ `LlmService`（业务封装）。

### 6.4 任务 / 主线 / 支线体系

- 领域（`domains`）承载头衔经验；主线（`quests.type=MAIN`）含章节结构与截止日，由 AI（M3）拆解；支线（`SIDE`）周期习惯，看重连击。
- 排程生成 `tasks` 时间块；完成专注产生 `sessions`，结算 CI 币与经验。
- 相关 UI：`feature/quest`（领域/任务编辑、路线生成、导入）、`feature/today`（当日时间线、开始/结束计时）。

### 6.5 商城与每日精选

- `ShopScreen` + `ShopRepository` 管理货架（`shop_items`）与购买（`purchases`）。
- `DailyShop`（`core/economy`）每日抽取 4 个折扣位（`daily_picks`），品质权重 45/35/15/5（普通/稀有/史诗/传说）。
- `PurchaseBoard` / `DefaultShopItems` / `DefaultPurchases` 提供默认数据与赎回面板。
- 商品 AI 估价走 `LlmTaskType.ITEM_PRICING`，锚定现实价 × 折扣系数（见方案文档 §3.2）。

### 6.6 复盘统计 `feature/stats`

- `StatsViewModel.computeStats` 纯本地聚合：总专注时长、按领域分布、完成率、计划 vs 实际（预估偏差）、**周热力图（7×24 格）**、每日专注分钟、任务明细、CI 收支。
- 支持本周/本月周期、按状态/领域筛选。
- **图表库现状**：依赖中未引入 Vico，热力图等图表为自绘或占位，待补齐。
- LLM 洞察（`analyze`）显式按钮触发，可不用；CSV 导出经 `CsvExporter` 落系统下载目录。

### 6.7 小组件与前台服务

- 计时走前台服务 `TimerService`（`foregroundServiceType="specialUse"`），保证不被系统杀。
- 两个 Glance 小组件：今日时间线（`TodayWidget`）、当前任务计时（`TimerWidget`）。
- **任何改动 task / session 数据的地方，结束后要调 `CiWidgetUpdater.updateAll(context)`**，否则桌面小组件不刷新。
- `DailyRefreshWorker` 在每日 00:00 附近跑，目前只刷新商店精选。

### 6.8 导入导出 `core/porting`

- `CiImport` / `ShopImport` / `ImportPreview` / `JsonText` 负责 JSON 导入预览与落地。
- `CsvExporter`（在 `feature/stats`）导出 sessions 明细 CSV。

## 七、设计系统（约束较硬）

- **`core/designsystem/Color.kt` 是全工程唯一允许写字面量颜色的地方。** 其余任何位置一律走 `MaterialTheme.colorScheme` 或 `CiTheme.colors`。
- 不占用 M3 角色的语义色（收入/支出/品质/难度/任务四态/热力色阶）定义在 `CiColors.kt`，全部由 `CiColors.from(scheme, isDark)` 从当前 ColorScheme 派生，亮/暗自动跟随。取用：`CiTheme.colors.income` 等。
- 间距、圆角、尺寸分别走 `CiSpacing` / `CiShapes` / `CiSizes`，不要写裸 `dp`。
- 小组件另有一份 `WidgetColors.kt`，接同一份 ColorScheme，改配色时两边都要顾到。
- 导航栏图标是**手绘 PNG**（`drawable-xxxhdpi` + `drawable-night-xxxhdpi` 两套亮/暗），不是 vector，`MainActivity` 用 `Image(painterResource(...))` 而非 `Icon`。

## 十二、关键约定与避坑

1. **改 Entity 要补迁移**：Room 当前 `version = 5`，已有 v1→v5 migration；以后每次改 Entity 都必须提升版本并追加 migration。
2. **Widget 刷新**：任何改动 `task` / `session` 后必须 `CiWidgetUpdater.updateAll(context)`。
3. **时间表达三件套**：`epochDay` / 当日分钟数 / 毫秒时间戳，改动前务必对齐（§4.4）。
4. **颜色约束**：字面量颜色只允许在 `Color.kt`；语义色走 `CiTheme.colors`；小组件配色两边同步。
5. **奖励公式集中**：所有经济计算在 `Economy`，别散到 Repository / UI；结算落地在 `TimerRepository.stopSession`。
6. **LLM 离线兜底**：`resolveEndpoint` 返回 null 是正常路径，调用方必须兜底，不能报错。
7. **排程最小扰动**：`Scheduler` 优先保原位，塞不下返回 `unplaced` 交 UI，不静默丢弃。
8. **语言约定**：代码注释、KDoc、UI 文案、测试方法名一律中文；测试方法名用反引号包裹的中文短句。
