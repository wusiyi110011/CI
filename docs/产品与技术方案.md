# 游戏化 AI 学习日程应用 —— 产品与技术方案 v0.1

> 目标设备：三星 Galaxy Tab S11 Ultra（平板，12G+512G）
> 形态：Android 原生应用 + 主屏幕小组件
> 定位：AI 自动排程 + 游戏化激励 + 数据复盘 三合一的个人学习操作系统

---

## 一、竞品调研结论（借鉴什么、不借鉴什么）

| 产品 | 借鉴 | 不借鉴 |
|------|------|--------|
| **LifeUp（人升）** | 游戏化框架最成熟：金币/经验/属性/成就/商店/背包，商店物品完全自定义（现实奖励、休息时间、开箱等） | 无 AI 排程，任务需全手动创建；定价靠用户拍脑袋 |
| **Habitica** | 主线（Todo/Daily）与习惯（Habit）分轨的思路、连击（streak）机制 | 社交/公会系统（个人使用不需要）；自定义弱 |
| **Motion** | AI 排程核心逻辑：任务只给「截止时间+预估时长+优先级」，引擎自动铺进日历；任何变动触发全天重排 | 订阅制云端服务，重度依赖会议场景 |
| **Reclaim** | 「习惯守护」思路：习惯类日程有优先级（P1-P4），被挤占时自动找下一个可行时段补回，而不是直接消失 | 同上 |
| **aTimeLogger / Toggl** | 复盘的数据形态：饼图（时间分配）、柱状图（趋势）、日/周/月报告、目标时间(上限/下限)达成率、CSV 导出 | 纯记录工具，无计划对比 |

**本项目的差异化**：Motion 的自动排程 + LifeUp 的游戏化经济 + Toggl 的复盘，且大模型可本地可云端。市面上没有三者合一的产品。

## 二、核心概念与命名

- **应用名（暂定）**：`CIM`（可再议）
- **奖励点命名建议**（选一个）：
  1. **星尘（Stardust）**⭐ 推荐：中性、耐看、和「主线/支线」的探索感一致
  2. 燃料（Fuel）：契合「攻坚主线」的推进感
  3. 光年 / 算力 / 灵感值
  以下文档统一用「星尘」指代。
- **主线（Main Quest）**：当前全力攻克的领域/大目标（如「3 个月拿下深度学习」）。同一时间**只允许 1~2 条主线**，由 AI 拆解为章节（阶段）→ 关卡（周任务）→ 步骤（每日时间块）。
- **支线（Side Quest）**：习惯养成与长期小目标（早睡、背单词、健身、阅读）。特点是周期性重复、单次耗时短、看重连击（streak）而非进度。

### 主线/支线的分配建议（你说还没想好，这是我的方案）

| 维度 | 主线 | 支线 |
|------|------|------|
| 数量上限 | 1~2 条 | 3~6 条 |
| 每日时间占比 | 60~70% 的可支配学习时间 | 每条 10~40 分钟 |
| 排程方式 | AI 按截止日期倒排，占据整块深度时段（≥45 分钟） | 类似 Reclaim「习惯守护」：给定频率+时长窗口，AI 见缝插针 |
| 奖励结构 | 星尘大额、随章节进度有里程碑奖励（Boss 奖励） | 星尘小额、连击加成（streak 越长倍率越高，断签重置） |
| 失败处理 | 顺延并重排后续计划 | 当天错过则作废，不补（习惯的意义在于当天做） |

## 三、功能模块设计

### 3.1 AI 排程引擎（核心）

**输入层**：
1. 你用自然语言描述目标：「我要学 xxx 领域，每天大概能投入 3 小时，预计 2 个月」
2. AI 生成**学习路线草案**（学什么、推荐哪些网课/书/项目、阶段划分），你确认/修改后成为主线
3. 固定日程（吃饭、上课、睡觉）和支线习惯作为约束条件

**排程规则（借鉴 Motion，但简化为个人可控的确定性算法 + LLM 辅助）**：
- 每个任务有：`预估时长`、`截止时间`、`优先级`、`可拆分性`、`偏好时段`（如深度学习任务偏好上午）
- **重排触发**：你说「明天下午 2-5 点有事」→ LLM 解析成「占位事件」→ 排程引擎把受影响任务重新塞入本周剩余空档，主线优先保住截止日期，支线按 Reclaim 式降级顺延
- **关键设计**：排程的"骨架计算"用本地确定性算法（贪心+优先级队列），LLM 只负责 ①自然语言理解 ②生成学习路线 ③调整建议的解释。这样没网/没 API 时排程照样能用，LLM 只是让它更聪明。
- 手动添加/拖动调整永远可用，手动调整的块标记为「锁定」，AI 重排不碰它。

### 3.2 星尘经济系统（完备计算方案）

**挣星尘（收入端）—— 公式固定、透明，不由 LLM 临场发挥**：

```
单次任务星尘 = 基础值 × 难度系数 × 专注系数 + 连击加成
  基础值   = 实际专注分钟数 × 1（即 1 分钟 = 1 星尘）
  难度系数 = 轻松 0.8 / 一般 1.0 / 烧脑 1.3 / 攻坚 1.6（创建任务时 AI 预估，可改）
  专注系数 = 按时完成 1.0；中途放弃按比例 0.5；超时完成 0.9
  连击加成 = 支线专属：连续 7 天 +10%，30 天 +25%，封顶 +50%
里程碑奖励 = 主线每完成一个章节，一次性 +(该章节总星尘 × 30%)
```

设计原则：**星尘只能通过专注时间产出**（小组件的开始/结束记录就是「挖矿」动作），日均可挣 200~300 星尘，月产出约 6000~9000。

**花星尘（支出端）—— LLM 自动定价，锚定现实货币**：

```
锚定汇率：1 元人民币 ≈ 20 星尘（即日均 3~4 小时专注 ≈ 挣 10~15 元"虚拟工资"）

现实物品（手机、电影票、游戏充值、视频 VIP）：
  标价 = 现实价格(元) × 20 × 折扣系数
  折扣系数 = 0.3~1.0，由物品的「奖励属性」决定：
    - 纯消费享乐（游戏充值、奶茶）：1.0（全价，克制冲动）
    - 有益消遣（电影、买书、约饭）：0.6
    - 投资自己（课程、装备、生产力工具）：0.3（鼓励购买）

虚拟奖励（休息 30 分钟、打一局游戏、刷 1 小时视频）：
  标价 = 消耗的分钟数 × 1.5（休息比挣钱贵 50%，保证"专注 3 小时才能换 2 小时躺平"）
```

**添加流程（要容易）**：商城页输入「iPhone 17 / 看一场电影 / 王者充 648」→ LLM 联网或凭知识估现实价格 → 自动判断奖励属性给折扣系数 → 生成标价和图标 → 你一键确认或手动改价。大件支持「储蓄进度条」（星尘先冻结、攒够解锁）。

**防通胀**：所有参数存在「经济配置表」里可调；每月复盘页显示收支平衡图，若星尘大量结余，AI 建议上调物价或提高难度。

### 3.3 主屏幕小组件（Widget）

- **大尺寸组件（4×3 或 5×3，平板屏幕大）**：今日任务时间线列表，每项显示 时间段/任务名/主线或支线标记/预计星尘
- 每项右侧一个按钮：**▶ 开始**（进入计时，组件顶部变为进行中状态+已计时时长）→ **⏹ 结束**（弹出快速评价：完成/部分完成，立即结算星尘）
- 附带小尺寸组件（2×2）：只显示「当前/下一个任务 + 开始按钮」
- 技术：Jetpack **Glance**（Compose 风格的 widget 框架），计时用前台服务保证不被杀

### 3.4 应用内日程视图

- **日视图**：垂直时间线（timeline），计划块 vs 实际记录块双轨对照（左计划右实际），完成的打勾发光，跳过的变灰
- **周视图**：7 列网格，可拖动调整任务块（拖动即「锁定」）
- **月视图**：热力图日历（每天按专注时长深浅着色）+ 主线里程碑标记
- 顶部分段控件切换 日/周/月

### 3.5 分析与复盘（不开 LLM 也必须好用）

**内置统计（纯本地计算，永远可用）**，借鉴 aTimeLogger/Toggl + 时间记录法社区的成熟做法：

1. **时间账本**：日/周/月的时间分配饼图（按主线/支线/领域）、专注总时长柱状趋势图
2. **计划 vs 实际**：完成率（按任务数和按时长两个口径）、预估偏差（预估 60 分钟实际 90 分钟 → 显示「你的预估平均乐观 35%」，反哺后续排程的时长预估）
3. **专注质量**：黄金时段热力图（一周 7×24 格，哪些时段完成率最高）、平均单次专注时长、中断/放弃率
4. **习惯面板**：每条支线的连击日历（GitHub 风格打卡格子）、坚持率
5. **经济面板**：星尘收支曲线、商城消费记录、储蓄进度
6. **周报/月报**：自动生成结构化报告页（本周总专注、对比上周 ↑↓、最佳的一天、被推迟最多的任务），可导出 CSV

**LLM 复盘（可选开关，明显的「使用 AI 分析」按钮）**：
- 把上述统计数据打包成结构化摘要喂给模型，输出：模式洞察（「你周三下午的放弃率是平时 3 倍，前面通常排了 4 小时连续主线」）、归因假设、下周排程调整建议（一键应用到排程引擎）
- 复盘对话模式：可以追问「为什么我最近效率低」

### 3.6 模型分工（本地 + API 双通道）

| 任务 | 首选 | 理由 |
|------|------|------|
| 生成学习路线、深度复盘分析 | **API 大模型**（Claude / DeepSeek / GLM，OpenAI 兼容接口，可配多个 Key） | 需要知识面和推理力 |
| 临时调整的自然语言解析（「明天下午有事」→ 结构化占位事件） | **本地小模型** | 高频、低延迟、离线可用、隐私 |
| 商品估价 | API 优先，离线时本地模型兜底 | 需要价格常识 |
| 周报摘要润色 | 本地小模型 | 数据已本地算好，只是组织语言 |

- 本地方案：**MediaPipe LLM Inference API**（Google 官方，集成最省事，支持 GPU）跑 **Qwen3-4B 或 Gemma3-4B int4 量化**（约 2~3GB，12G 内存的 Tab S11 Ultra 无压力）；备选 llama.cpp + Vulkan
- 设置页提供「模型路由表」：每类任务可手动指定 本地/某个 API/关闭

## 四、技术架构

```
语言/UI     Kotlin + Jetpack Compose（应用） + Glance（小组件）
架构        MVVM + Repository 模式，单模块起步按 feature 分包
数据库      Room (SQLite)，全部数据本地，支持导出备份(JSON/CSV)
后台        前台服务(专注计时) + WorkManager(每日排程刷新、连击结算)
排程引擎    纯 Kotlin 确定性算法（区间调度：贪心 + 优先级），独立模块可单测
LLM 接入    Retrofit/OkHttp(OpenAI 兼容 API，SSE 流式) + MediaPipe GenAI(本地)
            统一抽象为 LlmGateway 接口，路由表决定走哪个实现
图表        Vico（Compose 原生图表库）
API Key    Android Keystore 加密存储，绝不明文
```

**核心数据表草案**：`quests`(主线/支线定义) → `tasks`(排程生成的任务实例) → `sessions`(开始/结束的实际记录) → `ledger`(星尘流水) + `shop_items` / `purchases` / `blockers`(占位事件) / `llm_config`

## 五、开发路线图

| 阶段 | 内容 | 里程碑标准 |
|------|------|-----------|
| **M1 骨架**（先能用） | 任务 CRUD、日/周视图、手动排程、专注计时、星尘挣取公式、Room 落库 | 能手动安排一天并记录完成 |
| **M2 游戏化** | 主线/支线体系、连击、商城(手动定价)、小组件(开始/结束) | 平板桌面一键开始任务 |
| **M3 AI 排程** | API 接入、学习路线生成、确定性重排引擎、「明天有事」自然语言调整 | 说一句话即可重排当天 |
| **M4 复盘** | 全部内置统计图表、周报、LLM 可选分析、商品 AI 估价 | 周报可看可导出 |
| **M5 本地模型** | MediaPipe 集成、模型路由表、离线兜底 | 断网时核心功能不降级 |
