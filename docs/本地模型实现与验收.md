# Qwen3.5-2B + MNN 本地模型实现与验收

## 固定版本

- 推理引擎：MNN 3.6.1，源码 tag `3.6.1`，commit `d407447`。
- 模型：`MNN/Qwen3.5-2B-MNN`，revision `b9ae8c8f3da3fceb4278b558a747286b8a087dbe`。
- 模型文件：12 个，总计 1,386,694,949 字节；每个文件的固定大小与 SHA-256 见 `LocalModelManifest.kt`。
- Android：只交付 `arm64-v8a`，NDK `27.2.12479018`、CMake `3.22.1`，原生库使用 16KB 页对齐。

APK 只带约 10MB 的 MNN/JNI 原生运行库，不包含 1.39GB 模型。用户在设置页下载后，模型位于应用专属目录：

```text
files/local-model/qwen3.5-2b-mnn/revisions/<revision>/
```

## 构建 MNN 与 JNI

先以 MNN 3.6.1 源码构建 `arm64-v8a/libMNN.so`，需启用 `MNN_BUILD_LLM`、`MNN_BUILD_LLM_OMNI`、`MNN_LOW_MEMORY`、`MNN_CPU_WEIGHT_DEQUANT_GEMM`、`MNN_SUPPORT_TRANSFORMER_FUSE`、`MNN_ARM82` 与 `MNN_USE_LOGCAT`。视觉构建还要启用 `LLM_SUPPORT_VISION`。生产配置默认使用 CPU；OpenCL 仅保留给后续真机对比，不作为默认后端。

随后执行：

```bash
native/mnn/build_android.sh <MNN-3.6.1 源码目录> <MNN arm64-v8a 构建目录>
```

脚本会把固定的 `libMNN.so`、`libcimnn.so` 和 `libc++_shared.so` 写入 `app/src/main/jniLibs/arm64-v8a`。JNI 暴露加载、文本生成、RGBA 图片生成、取消与释放；生成采用逐 token 步进，使后台释放和用户取消能及时到达 native。

## 下载与安装

- WorkManager 唯一任务，默认约束为非计费网络。
- 下载期间使用数据同步前台服务通知。
- 每个文件写入 `.part`，服务端支持时使用 HTTP Range 续传。
- 文件按大小与 SHA-256 校验，失败会删除损坏文件并自动再试一次。
- 下载前要求“剩余字节 + 512MiB”可用空间。
- 所有文件通过后，staging 目录才原子移动为固定 revision；不会向运行时暴露半成品。

暂停和取消会停止 Work；暂停保留 `.part`，取消后仍可重新开始，删除会同时停止下载和本地运行时并清除整个模型目录。

## 运行时与路由

运行时只持有一个 native handle，并通过单队列串行生成。应用每次冷启动均为关闭状态；`MainActivity.onStop` 立即发出取消、清空队列并释放模型。启动流程固定为文件检查、MNN 加载、8 token 冒烟推理，只有全部通过才进入“已开启”。

本地路由不会回退到云端。选择本地模型后，未下载、未启动、推理失败和取消都会返回本地来源的结构化错误。旧版直接保存的 DeepSeek/MiMo endpoint id、`off` 与空默认值保持兼容。

任务预算：

| 任务 | 思考 | 最大 token |
|---|---:|---:|
| 学习路线 | 开 | 2048 |
| 深度复盘 | 开 | 1536 |
| 自然语言解析 | 关 | 256 |
| 商品估价 | 关 | 384 |
| 头衔生成 | 关 | 256 |
| 图片理解 | 关 | 512 |

## SM-X930 基线

目标真机：三星 `SM-X930`，Android 16 / API 36，`arm64-v8a`，MT6991，Mali-G925，约 12GB 内存。

首次实现时的真机记录：

- 空载冷启动约 654ms，约 158MB PSS、295MB RSS。
- 应用内下载 12 个文件全部完成校验和原子安装。
- CPU 首次加载加 8 token 冒烟推理约 18 秒，满足 60 秒闸门；服务进入“已开启”，无崩溃或 OOM。
- 加载后约 1.67GB PSS、1.80GB RSS，其中约 1.35GB 为只读 mmap 权重。
- 退到后台后确认 native 释放；约 10 秒后回落到 88MB PSS、171MB RSS，且回到前台仍保持“已关闭”。

20 次连续文本、5 次加载释放、生成中取消、RGBA 视觉与 CPU/OpenCL 正式比较仍需作为后续耐久验收。OpenCL 只有满足连续 20 次无错、速度提升至少 20%、内存增幅不超过 15% 才允许启用。
